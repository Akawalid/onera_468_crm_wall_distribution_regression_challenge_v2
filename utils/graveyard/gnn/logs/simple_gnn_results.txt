train_simple_gnn.py -- local training run results
===================================================

Script: utils/train_simple_gnn.py, model utils/simple_gnn.py (distance-weighted
GraphSAGE-style GNN -- see module docstrings for full methodology/rationale).
Built as a deliberately lighter baseline than utils/offset_gnn.py's OffsetGNN, to find
where GNNs of any kind start beating the pointwise baselines in utils/base_models.py, and
where OffsetGNN's much heavier offset-attention machinery actually earns its extra cost.

Run environment: local machine, GPU (CUDA), venv: ~/.venvs/fpml.
Data: mini-automl/data/ (splitv2/), full labeled dataset -- n_train=252, n_test1=144.
Model selection: best val_loss on a 10%-of-train held-out split (25 sims), NOT
test_phase1 -- so the test_phase1 numbers below are never used for the stopping/checkpoint
decision.

Run 2 -- +coords feature, +distance-weighted aggregation, k=20, 3 layers, +LayerNorm/residual
-------------------------------------------------------------------------------------------------
Changes vs. Run 1 (utils/simple_gnn.py, utils/train_simple_gnn.py):
  1. static_feats now includes standardized (x, y, z) node coordinates -- previously
     omitted entirely; the mesh is identical across all 252 sims, so raw position is a
     cheap, highly informative per-node feature (already used by the pointwise
     XGBoost/LightGBM baselines in base_models.py).
  2. SimpleGraphConv aggregation switched from a plain unweighted mean to inverse-distance
     weighted (compute_inverse_distance_weights) -- a neighbor 1cm away no longer counts
     the same as one 10cm away. Weights are a fixed geometric quantity computed once from
     the static mesh and reused across every layer/sim/epoch.
  3. k: 10 -> 20 neighbors; n_layers: 2 -> 3, for a wider effective receptive field.
  4. Added LayerNorm after each conv layer, plus a residual add on every layer past the
     first (first layer changes dimensionality in_dim -> hidden_dim so has nothing
     shape-compatible to add against).

Command:
  python3 utils/train_simple_gnn.py --hidden_dim 64 --n_layers 3 --k 20 \
      --dropout 0.2 --weight_decay 1e-5 --epochs 100 --patience 15

Wall time: 78m 25s (100/100 epochs, patience never triggered -- still finding new val_loss
lows as late as epoch 98; per-epoch cost ~43.5s, up from ~10s in Run 1, from k doubling the
edge count and the extra layer).
Best checkpoint: epoch 98 (val_loss=0.00165)

Takeaways
---------
- Run 2 vs. Run 1 (both early-stopping-selected checkpoints): R2 0.657 -> 0.942,
  worst_rMAE 0.099 -> 0.049 (roughly halved), mean_rMAE 0.077 -> 0.032 (more than
  halved), mean_KLw 2.153 -> 1.433 (33% lower, lower is better), max_KLw 2.642 -> 2.019
  (24% lower). All four changes were bundled into one run, not ablated individually --
  the coordinates fix (previously missing entirely) is suspected to be the single
  biggest contributor, since it gives the model a cheap per-node positional signal the
  pointwise XGBoost/LightGBM baselines already had and the 2-hop graph alone couldn't
  reconstruct.
- Neither run triggered early stopping (patience=15) -- Run 2 was still setting new
  val_loss lows as late as epoch 98/100, so more epochs and/or a larger patience budget
  would likely still help.
- Cost: Run 2 is ~4x slower per epoch than Run 1 (k=20 doubles edge count, 3 vs 2 layers,
  plus LayerNorm), 78m vs 19m total for 100 epochs -- worth it here given the metric
  gains, but a real cost if iterating further.
- Model checkpoints are saved to utils/simple_gnn_model.pt (Run 2's epoch-98 weights,
  overwriting Run 1's) -- rerun train_simple_gnn.py with Run 1's flags to regenerate
  that comparison point if needed.
- test_phase2 R2=0.905 vs. test_phase1's 0.942 -- worse across every metric but not
  drastically, consistent with phase2 being the known harder/more OOD split for every
  other model in this repo (e.g. gp_pod_model_results.txt: GP+POD R2 ~0.97 phase1 ->
  ~0.86 phase2). Reads as a normal generalization gap, not a red flag specific to this
  model.
