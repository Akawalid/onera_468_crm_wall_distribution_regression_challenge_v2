# ONERA 468 CRM Challenge rho: Starting Kit

## Goal

Predict the non-dimensionalized volumetric density $\rho$ at every point of the fluid
domain, for aerodynamic conditions not seen during training.

## Data structure (`input_data/`, downloaded from Codabench)

| File | Shape | Description |
|---|---|---|
| `train_data.npy` | (n_train x 260,774, 9) | Train inputs |
| `train_labels.npy` | (n_train x 260,774, 1) | Train target (rho) |
| `test_data.npy` | (n_test x 260,774, 9) | Test inputs (no labels) |
| `component_labels_unique.npy` | (260,774,) | Component id per wall point |
| `component_map.json` | -- | `{id: component_name}` (wing/pylon/fuselage/nacelle) |

The 9 columns of X are: `x, y, z, nx, ny, nz, Minf, AoA, Pi`

## Contents of the kit

- `starting_kit.ipynb` -- the main notebook, meant to be read in order.
- `kit_utils/` -- all the reusable code (metrics, models, plots), imported by the
  notebook. Look here directly if you want to understand or tweak an
  implementation detail.
  - `metrics.py` -- R2, wrMAE, KLw (mean_KL) and their bootstrap confidence
    intervals, formulas identical to `scoring_program/scoring.py`.
  - `data.py` -- loading the train data and component masks, plus
    `mach_fold_splits` (leave-two-Machs-out cross-validation) -- not used by
    the notebook's default flow anymore (see below), but still there and
    ready if you need it.
  - `download.py` -- downloads `input_data/` straight from Codabench the
    first time the notebook runs.
  - `mean_baseline.py` -- Baseline A: predicts the global training mean,
    ignoring the inputs entirely (section 2.1 of the notebook).
  - `pod_gp_baseline.py` -- Baseline B: POD (PCA) + one Gaussian Process per
    mode, Optuna-tuned (section 2.3 of the notebook). Also the model behind
    `submission_pod_gp.zip`.
  - `lgbm_baseline.py` -- pointwise LightGBM baseline, same model as
    `utils/base_models.py`. Not called from the notebook anymore, kept as a
    reference/starting point if you want to swap it back in.
  - `pca_plots.py` -- visual diagnostics (error on the aircraft, PCA directions
    of the error, slices).
- `baselines/` -- heavier reference baselines, run on their own (not from the
  notebook).
  - `mlp_klw.py` -- production-scale full-field MLP trained with the same
    differentiable KLw loss, see section 2.2 of the notebook.
- `submission.zip` -- generated by the notebook (section 5); currently the mean
  baseline. Unzip to get `model.py`.
- `submission_pod_gp.zip`, `submission_knn.zip`, `submission_isomap_rbf.zip`,
  `submission_global_mlp.zip`, `submission_mlp_klw_with_dotpt_file.zip` --
  ready-made, stronger alternative submissions, one per baseline explored in
  the parent project. Unzip any of them to get its `model.py`:
  - `submission_pod_gp.zip` -- POD + Gaussian Process (Optuna-tuned), same
    model as `kit_utils/pod_gp_baseline.py`.
  - `submission_knn.zip` -- input-space kNN on (Minf, AoA, Pi).
  - `submission_isomap_rbf.zip` -- IsoMap (r=3) + RBF interpolation.
  - `submission_global_mlp.zip` -- global-field MLP (Peter et al. 2025
    architecture).
  - `submission_mlp_klw_with_dotpt_file.zip` -- MLP trained with the
    differentiable KL-divergence loss; ships a pretrained `.pt` file so it
    skips retraining between phase 1 and phase 2 (see the Data tab).
- `using_extra_packages/` -- how to bundle extra Python packages (e.g.
  LightGBM) into a submission; see the Extra packages tab.


## Running the starting kit

```bash
pip install -r requirements.txt
jupyter notebook starting_kit.ipynb
```

The notebook fits both baselines once on a random 80/20 split of the training
simulations (section 2), a couple of minutes total on CPU, POD+GP's Gaussian
Processes being the slower of the two. `baselines/mlp_klw.py` is heavier still
(production-scale network, hundreds of epochs) and is meant to be run
separately, ideally on a GPU.
